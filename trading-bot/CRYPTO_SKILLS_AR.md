# DRAK — تكييف مهارات Trader Skill للعملات الرقمية

هذا المجلد يضيف طبقة مستقلة من وظائف إدارة التداول الورقي لـ Binance Spot، مستوحاة من سير العمل الموثق في [Jakeschincariol/trader-skill](https://github.com/Jakeschincariol/trader-skill). لا تُنسخ مهارات الأسهم الأمريكية حرفيًا؛ بل تُستبدل مصادرها وقواعدها بما يناسب أزواج USDT الفورية.

## الحالة الأمنية

- هذا المكوّن **ورقي فقط**. لا يقرأ مفاتيح API، ولا يحتوي على عميل تنفيذ أوامر، ولا يرسل أو يلغي أو يعدّل أوامر.
- جلب بيانات السوق العامة يظل في `drakbot/api.py` وبمسارات قراءة فقط.
- لا توجد رافعة مالية أو بيع على المكشوف أو رموز مرفوعة اصطناعيًا في قائمة الفرز.
- كل تذكرة هي للعرض فقط، وتحتاج مراجعة بشرية؛ ولا تتحول إلى طلب Binance.
- لا تضع مفاتيح API أو كلمات مرور أو ملفات حساب داخل المستودع.

## تكييف الوظائف الإحدى عشرة

| مهارة Trader Skill الأصلية | المقابل في DRAK |
|---|---|
| Copycat | قائمة متابعة يحددها المستخدم؛ لا نسخ لمحافظ أشخاص |
| News | مطابقة أخبار يزوّدها مصدر خارجي مع أزواج المتابعة، مع وسم غير المؤكد |
| Budget | حساب حجم مركز Spot وفق رأس المال والرسوم والانزلاق والوقف وقيود الزوج |
| Pelosi | أحداث السوق المعلنة: إدراج، شطب، فتح قفل، صيانة؛ لا تتبع سياسي |
| Analyst | لقطة فنية من شموع مغلقة ومؤشرات EMA/RSI/MACD/ATR والحجم |
| Screener | فرز الأزواج حسب السيولة وفارق العرض والطلب وأهلية Spot |
| Risk | بوابة مستقلة PASS/BLOCK تعيد فحص المخاطرة والاحتياطي والخسارة اليومية |
| Broker | تذكرة يدوية معلوماتية مرتبطة ببصمة الخطة؛ لا اتصال بوسيط |
| Tax | سجل FIFO ورقي للأرباح المحققة والرسوم، وليس حسابًا ضريبيًا |
| Alerts | تنبيهات سعرية للإشعار فقط، لا تبيع ولا تشتري |
| Rebalance | تحليل الفروقات بين الأوزان الحالية والمستهدفة، بلا تنفيذ |

## إعداد البداية

الإعداد المحافظ الافتراضي:
- رأس المال الافتراضي: 11 USDT.
- احتياطي نقدي: 20%.
- حد أقصى للمركز الواحد: 70% من رأس المال.
- المخاطرة النظرية عند الوقف: 1% من رأس المال (0.11 USDT قبل أي تغيير).
- رسم افتراضي: 0.10% لكل جهة، وانزلاق افتراضي 0.05% لكل جهة.
- حد أدنى للقيمة الاسمية: 5 USDT افتراضيًا؛ يجب استبداله بمرشح الزوج الحالي من Binance قبل تقييم أي اقتراح.
- مركز مفتوح واحد كحد أقصى، وثلاثة اقتراحات في اليوم، وإيقاف اقتراحات اليوم عند خسارة 3%.

**مهم:** مع رأس مال 11 USDT، قد تجعل قيود الحد الأدنى للطلب وحجم المخاطرة كثيرًا من الإشارات غير قابلة للتنفيذ حتى في المحاكاة. وظيفة النظام أن يحجبها بدل رفع المخاطرة لتجاوز الحد الأدنى. هذه ليست توصية لفتح أي صفقة.

## استخدام المكتبة

من مجلد `trading-bot`:

```python
from drakbot.crypto_skills import (
    CryptoRiskConfig, SymbolFilters, size_spot_position,
    risk_gate, build_manual_ticket, analyze_candles,
)

config = CryptoRiskConfig()
proposal = size_spot_position(
    "BTCUSDT", entry_price=100.0, stop_price=99.5, config=config,
    filters=SymbolFilters(min_qty=0.00001, step_size=0.00001,
                          tick_size=0.01, min_notional=5.0),
)
verdict = risk_gate(proposal, config)
print(proposal)
print(verdict)
# A display-only ticket can be built only from the exact risk-approved proposal:
# ticket = build_manual_ticket(proposal, verdict)
```

اختبارات الوحدة:

```bash
python -m pytest -q
```

## قيود البيانات والتقييم

- التحليل الفني يأخذ كائنات الشموع التي يمررها المستدعي، ويشترط 60 شمعة على الأقل وترتيبًا زمنيًا فريدًا.
- يجب على المستدعي استبعاد الشمعة غير المكتملة قبل استدعاء التحليل.
- لا يُفترض أن أخبارًا أو أحداثًا ما صحيحة لمجرد ورودها؛ يُحفظ المصدر وتبقى علامة التحقق منفصلة.
- لا تُعتبر نتيجة PASS توصية شراء أو ضمانًا؛ إنها تحقق آلي من حدود محددة فقط.
- يجب اختبار التكاليف ومرشحات Binance وبيانات تاريخية محفوظة خارج العينة قبل تقييم أي استراتيجية.

## تشغيل الأوامر

من داخل مجلد `trading-bot`:

```bash
python -m drakbot.skills_cli watchlist --input examples/watchlist.json
python -m drakbot.skills_cli size --input examples/spot-plan.json
python -m drakbot.skills_cli risk --input examples/risk-check.json
python -m pytest -q
```

أمر `ticket` لا يقبل رقمًا ثابتًا أو قديمًا: شغّل `risk` أولًا، ثم انسخ قيمة `fingerprint` من نتيجته إلى ملف تذكرة العرض مع **الخطة نفسها دون أي تعديل**. أي تغيير في السعر أو الكمية أو الوقف يبطل البصمة ويستلزم فحص مخاطر جديدًا.
